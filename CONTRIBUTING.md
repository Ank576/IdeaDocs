# Contributing to IdeaDocs

We welcome contributions to IdeaDocs! This document provides guidelines for contributing ideas, PRDs, and technical documentation.

## How to Contribute

### 1. Product Ideas
- Place your idea in the `ideas/[domain]/` folder
- Use the template from `templates/idea-template.md`
- Follow the naming convention: `descriptive-idea-name.md`

### 2. Product Requirement Documents (PRDs)
- Create a new folder in `prds/[product-name]/`
- Follow the template from `templates/prd-template.md`
- Use semantic versioning: `v1.0-prd.md`, `v2.0-prd.md`
- Store supporting assets in `assets/` subfolder

### 3. Technical Documentation
- Organize by category: `architecture/`, `implementation-guides/`, `research/`
- Use the template from `templates/tech-doc-template.md`
- Include code examples and diagrams where relevant

## Submission Process

1. Fork the repository
2. Create a feature branch: `git checkout -b feature/your-contribution-name`
3. Add your files following the structure
4. Commit with clear messages: `git commit -m "Add [type]: Brief description"`
5. Push to your fork
6. Open a Pull Request with a description

## Quality Standards

- Use clear, professional language
- Include relevant examples
- Ensure proper formatting and structure
- Reference existing documents where applicable
- Update the README if introducing new categories

## Code of Conduct

- Be respectful and constructive
- Provide actionable feedback
- Celebrate diverse perspectives
- Help others learn and grow

Thank you for contributing!
